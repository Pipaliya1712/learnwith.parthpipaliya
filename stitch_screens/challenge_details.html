Event-Driven Notification Engine

Project: CloudScale Enterprise Hub

HARD BACKEND REDIS

subject Overview

In this challenge, you will architect and implement a high-throughput notification engine capable of handling millions of concurrent events. The system must decouple the event source from the delivery mechanism using a message broker, ensuring high availability and fault tolerance.

architecture-specs.yaml content_copy 
engine:
  throughput: 100k/sec
  retry_policy: exponential_backoff
  max_retries: 5
  persistence: redis_streams
  dead_letter_queue: enabled

business_center Project Context

The "CloudScale Enterprise Hub" has seen a massive surge in user activity. Currently, the monolithic API handles notifications synchronously, causing severe latency during peak hours. Your task is to extract this logic into a standalone microservice that consumes events from a Kafka or Redis stream.

"We need to ensure that even if our downstream email provider is down, the system doesn't lose user alerts. We need a robust queueing strategy." — Lead Architect

fact_check Acceptance Criteria

  • check
    Implement a consumer that listens to the `user.events` stream.
  • check
    Configure an exponential backoff strategy for failed notification attempts.
  • check
    Ensure exactly-once delivery semantics using idempotency keys.
  • check
    Write integration tests simulating provider timeouts.
